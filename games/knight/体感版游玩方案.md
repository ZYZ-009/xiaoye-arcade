# FATFIGHT 体感版 · 摄像头动作操控方案

> 目标：把 `gesture_tracker.html`（MediaPipe Pose+Hands 姿态捕捉）与 `index.html`（骑士跑酷引擎）融合，
> 做成**用身体动作操控骑士闯关**的网页体感游戏。保留全部现有玩法（严格 A/D 移动、空格二段跳、下蹲障碍五五开、空中红心回血），只把"按键"换成"动作"。

---

## 一、玩法概览

玩家站在摄像头前，通过**左右移动身体、原地起跳、蹲下、空中拍手**四种动作操控骑士：

| 你的动作 | 游戏操作 | 类比键盘 |
| --- | --- | --- |
| 身体向左 / 向右偏移 | 骑士向左 / 向右移动 | A / D |
| 身体回到画面中央 | 骑士静止（零惯性） | 不按键 |
| 原地跳起 | 跳跃（第一级） | W |
| 空中双手拍一下 | 二段跳（更高） | 空格 |
| 蹲下并保持 | 下蹲（穿过低障碍 / 天花板隧道） | 长按 S |
| 双手握拳 0.8 秒 | 暂停 / 继续 | P |
| 举手 3 秒（或点击按钮） | 开始一局 | 点击开始 |

核心体验：**"往左挪 = 往左走，站正 = 停，跳 = 跳，蹲 = 蹲"** —— 身体就是手柄。

---

## 二、动作映射表（主方案 · 推荐）

采用**"躯干位移 + 姿态瞬态"**组合，信号源彼此正交，误触率最低：

| 游戏输入 | 信号源（MediaPipe） | 判定规则 | 输出语义 |
| --- | --- | --- | --- |
| **左右移动** | 躯干中心 x = 均值(肩11/12.x, 髋23/24.x) | 归一化映射成摇杆值 `joy=(cx-0.5)*2`；死区 \|joy\|<0.10 视为 0 | 连续量 → 速度 ±280px/s |
| **跳跃** | 髋中心 y（或双踝 y 均值） | 向上速度 vy > 0.35/s（归一化）持续 ≥2 帧 → **上升沿触发一次** | jump 脉冲 |
| **下蹲** | 髋中心 y + 膝弯曲角 | 髋 y 低于站立基线 >0.12 **且** 膝角 <110° → 持续输出 | slideHeld 保持 |
| **二段跳** | 左右手腕 (15/16) | 游戏处于空中时，两腕距离 <0.15 且都在胸口高度 → **拍手触发一次** | doubleJump 脉冲 |
| **暂停** | 双手 21 点 | 两手掌心距离 <0.2 且五指均收起（握拳）保持 0.8s | pause 脉冲 |
| **开始** | — | 举手（任一腕 y < 肩 y）保持 3s，或点按钮 | 开始一局 |

### 映射的几何原理（为什么这样最稳）

- **左右**用躯干中心而不是手：躯干 x 平滑、抗抖动，天然就是"摇杆"；手一挥会乱晃。
- **跳与蹲共用髋部 y 却不冲突**：跳 = 髋 y 的**快速向上瞬态**（速度特征）；蹲 = 髋 y 的**低位稳态 + 膝盖弯曲**（姿态特征）。两者特征维度不同，可同时工作。
- **二段跳用手势**：因为跳跃时身体已在空中、髋 y 变化不可再用，改用"拍手"这个独立手势，干净利落。
- **画面镜像**：前置摄像头画面是镜像的，控制一律**以画面为参照**（画面中你往左 = 角色往左），所见即所得，不需要玩家做"反向思维"。

## 三、信号处理细节（决定手感的部分）

1. **校准基线**：进入游戏前 2 秒，让玩家"自然站直"，记录髋 y 基线、肩宽、膝角基线。此后所有阈值都以基线为参照（容忍不同身高、站位远近）。提供"重新校准"按钮。
2. **平滑**：躯干 x 用 EMA 低通（按帧率补偿，alpha≈0.35），跳跃/下蹲信号用 3 帧中值。
3. **死区与映射**：摇杆死区 0.10，线性映射到 ±MOVE_VX(280)；灵敏度滑块调节 `灵敏度 = 映射区间 / 死区`。
4. **事件锁存（关键）**：MediaPipe 在 CPU 上约 10–20fps，直接逐帧读会"断触"。因此：
   - 跳跃/二段跳/暂停 = **上升沿事件**，触发后锁存 150–200ms 交给游戏消费；
   - 下蹲 = **电平信号**，每帧刷新（蹲着就一直有效）；
   - 左右 = 连续量，低通即可。
5. **防误触**：跳跃需连续 2 帧速度达标；下蹲需同时满足髋降 + 膝弯两个条件；走路小晃动被死区吸收。
6. **失检保护**：连续 0.5s 未检测到人体 → 自动回到"静止"（相当于松开所有键），避免角色卡住。

## 四、输入系统架构（怎么"结合"）

游戏引擎**完全不动**，新增一个"动作→按键"翻译层，把结果注入现有的 `Input`：

```
摄像头 → MediaPipe(Pose+Hands) ──> motion.js 纯逻辑
                                      │  姿态 → {left,right,jump,doubleJump,slideHeld,pause}
                                      ▼
                              Input.inject(动作状态)   ← 新增的注入接口
                                      │
                              Input.consume()（现有）
                                      ▼
                              game.js 游戏引擎（零改动）
```

### 文件改动清单

| 文件 | 改动 |
| --- | --- |
| `js/motion.js`（**新增**） | ① 摄像头 + MediaPipe 启动（裁剪自 gesture_tracker：仅 Pose+Hands、无骨架绘制）② **纯函数** `parseMotion(pose, hands, cfg) → 动作状态`（核心判定全部在此，便于 node 测试）③ 平滑/锁存/校准逻辑 |
| `js/input.js`（改） | 增加 `inject(state)`：把动作状态写入内部 state（jumpQueued 等），键盘/触摸仍可用（兜底与调试） |
| `index.html`（改） | 引入 motion.js；新增摄像头画中画小窗（右下角，可开关）；校准/灵敏度/重新校准控件；教学模式覆盖层 |
| `js/ui.js`（改） | 增加"当前识别动作"可视化（左右/跳/蹲/拍手指示灯）与摄像头开关按钮 |
| `test/motion-check.js`（**新增**） | 用构造的 landmarks 数组单测 `parseMotion`：左移/回中/跳跃/蹲下/拍手/握拳各触发对应输出 |
| `README.md` | 体感模式说明 + 运行方式（必须 http:// 才能用摄像头） |

## 五、界面与交互设计

1. **摄像头画中画**：右下角 180×120 小窗，半透明，显示骨架叠加；可一键关闭（关闭后自动切回纯键盘模式）。
2. **校准流程**：开局提示"请站到画面中央，保持自然站姿 2 秒"→ 自动校准 → "✓ 已校准，向左挪一步试试"。
3. **动作指示灯**：HUD 下排 5 个小灯（← → 跳 蹲 拍手），识别到哪个亮哪个，玩家立刻知道系统怎么理解自己。
4. **灵敏度滑块**：3 档（迟钝 / 标准 / 灵敏），运行时即调。
5. **教学模式**（前 30 秒）：依次高亮"往左挪 → 站正 → 跳 → 蹲 → 跳起来拍手"，完成一项给金币。
6. **键盘兜底**：WASD/空格/S 全程可用（调试、演示、玩家偷懒都行），互不干扰。

## 六、闯关玩法设计（体感版特色）

1. **目标关制**（替代纯无尽）：每关给出目标，如"第 1 关：跑 600 米 + 吃 3 颗红心；第 2 关：900 米 + 躲过 5 组下蹲障碍…"。达成 → 进下一关，速度/障碍密度由关卡参数控制（复用现有生成系统，仅改参数）。
2. **运动能量条**：累计动作幅度（左右位移量 + 跳跃 + 下蹲 + 拍手）填充能量条，**满一次 +1 血**（配合红心可叠到上限 10）。给体感玩家"越动越强"的正向激励。
3. **连击段 / BOSS 关**（后期）：30 秒内连续"跳→蹲→跳→拍手"组合的高密度障碍段，验证全身协调。
4. **成绩**：距离 + 金币 + 红心 + 运动能量综合评分，存 localStorage 最高分。

## 九、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| CPU 推理帧率低（10–20fps） | 输入断触、延迟 | 事件锁存 150–200ms；上升沿触发；躯干低通平滑 |
| 动作误触发 | 乱跳/乱蹲 | 双条件判定（髋降+膝弯）；阈值+持续帧数；校准基线；灵敏度可调 |
| 多人/杂物入镜 | 骨架错乱 | 取置信度最高者；提示玩家单人正对镜头 |
| 光照差/穿深色衣服 | 检测不到 | 姿态丢失自动归零（静止）；提示调整光线 |
| file:// 打不开摄像头 | 完全不可用 | 页面内嵌提示 + README；必要时打包为本地 HTTPS 或桌面壳 |
| 摄像头隐私顾虑 | 心理障碍 | 明确"画面只在本地内存处理、不上传"；提供纯键盘模式 |
